## 3. Sub-Agent Team Structure & Operational Workflow
The development workflow is orchestrated by BaldHawk as Lead Project Manager, directing four specialized divisions:

1. **Asset & Art Specialist:**
   * Directs folder hierarchy in `Assets/Art/Sprites/` (`Grid/`, `Heroes/`, `Monsters/`, `UI/`).
   * Produces functional placeholder sprites and validates aspect ratio, PPU (Pixels Per Unit = 100), and visual readability before final art drop-in.
2. **Core Gameplay & Unity Engineer:**
   * Develops clean C# architecture: `GridManager.cs`, `TileCell.cs`, `UnitController.cs`, and hero specializations (`CedricUnit.cs`, `RoseTankerUnit.cs`, `RabbitMageUnit.cs`).
   * Builds summon and drag-and-drop merge mechanics.
3. **Data & Economy Balance Designer:**
   * Develops data architecture (`UnitDataSO.cs`, `LevelConfigSO.cs`, `WaveDataSO.cs`).
   * Enforces mathematical balance: Tier multipliers ($1.0\times$, $2.2\times$, $4.8\times$), dynamic summon formula ($\text{Cost} = 40 + (n-1) \times 10$), and Lobby Team CP integration.
4. **QA & Code Reviewer (Lead Gatekeeper):**
   * **Syntax & Namespace Integrity:** Validates syntax, namespace imports, event decoupling, and null-safety across all C# scripts.
   * **Unity API & Version Verification:** Strictly verifies all Unity Engine & Editor API calls against Unity 6 (`6000.6.x`) and Unity 2022.3 LTS specifications before any commit (prohibits hallucinated properties or deprecated members).
   * **Assembly Boundary Enforcement:** Enforces strict separation between Runtime assemblies and `Editor/` scripts, ensuring no `UnityEditor` calls leak into runtime code.
   * **Pre-Flight Gating:** Performs cross-script method signature synchronization, GUID/meta file validation, and headless pre-flight audits prior to any CI/CD push.
   * **Post-Mortem Root Cause Analysis:** Diagnoses CI build logs down to exact line numbers and implements preventive guardrails so failures never recur.

## 5. Mandatory QA Pre-Flight Gating & Zero-Defect Protocol (Anti-Regression SOP)
Untuk mencegah kegagalan build CI/CD dan regresi teknis, seluruh pengerjaan wajib mematuhi 5 gerbang kendali mutu (*Quality Gates*) berikut tanpa pengecualian:

### Gate 1: Unity Engine & Editor API Exact-Match Verification
* **Larangan Keras Berasumsi API:** Dilarang menebak nama properti/method Unity (misal: properti `PlayerSettings` orientasi layar, field `TextureImporter`, atau method obsolete).
* **Standar Unity 6 & LTS:** Semua pemanggilan API Unity wajib diverifikasi terhadap dokumentasi resmi Unity 6 (`6000.6.x`) dan 2022.3 LTS.
* **Separasi Editor vs Runtime:** Seluruh pemanggilan `UnityEditor` wajib berada di dalam folder `Assets/Scripts/Editor/` atau dibungkus blok `#if UNITY_EDITOR ... #endif` agar tidak merusak kompilasi runtime pemain.

### Gate 2: Cross-Script Signature & Namespace Synchronization
* **Audit Caller Menyeluruh:** Setiap kali memodifikasi signature method, nama event, atau parameter class di suatu script, QA wajib mencari dan mengaudit seluruh script pemanggil (*callers*) di seluruh proyek.
* **Namespace Resolution:** Pastikan semua namespace domain (`FantasyDefense.Core`, `FantasyDefense.Data`, `FantasyDefense.UI`, `FantasyDefense.Audio`, `Rampartbound.Editor`) telah diimpor dengan benar (`using ...;`) dan tidak ada ambiguous type reference.

### Gate 3: Asset Metadata & GUID Preservative Integrity
* **Validasi File .meta:** Setiap file C# script, ScriptableObject `.asset`, sprite PNG, dan prefab WAJIB memiliki file `.meta` pendamping dengan GUID 32-karakter heksadesimal yang utuh dan valid.
* **Pencegahan Missing References:** Jangan pernah menghapus atau membuat ulang file `.meta` dari aset yang sudah terhubung dalam Scene atau ScriptableObject.

### Gate 4: Pre-Commit & Pre-Push Definition of Done (DoD) Gate
Sebelum commit dibuat atau di-push ke repository remote (GitHub Actions / CI):
1. **Full Diff Audit:** Review setiap baris perubahan (`git diff`) untuk memastikan tidak ada unclosed `#region`, missing brackets `{ }`, atau unreferenced variables.
2. **Headless / Syntax Sanity Check:** Pastikan tidak ada script yang rusak atau memicu warning error kritis.
3. **Pilar Integrasi Scene:** Verifikasi bahwa `RampartboundSceneSetup.cs` dan `RampartboundQAValidator.cs` dapat berjalan bersih dengan zero unhandled exceptions.

### Gate 5: CI/CD Failure Zero-Tolerance Post-Mortem
* Jika suatu run CI/CD gagal:
  1. **Audit Log Sampai Baris Error Spesifik:** Download dan periksa log build hingga menemukan baris kode `error CSxxxx` yang tepat.
  2. **Identifikasi Titik Buta:** Analisis mengapa QA lokal melewatkan error tersebut.
  3. **Permanent Fix & Guardrail Codification:** Perbaiki kode secara tuntas dan mutakhirkan pedoman QA agar celah yang sama tertutup selamanya.

### Gate 6: End-to-End Playability, Intent & Anti-Clutter Gate (Gerbang Validasi Gameplay Nyata)
* **Larangan 'Green-Build Only' Assumption:** Lolos build CI/CD 0 error dan unit test hijau BUKAN jaminan pekerjaan selesai. QA wajib memvalidasi pengalaman pengguna (*User Experience*) dan keselarasan tujuan (*Gameplay Intent*).
* **Zero UI Raycast Blocker Guarantee:** Seluruh panel UI layar penuh yang transparan (seperti `BattleHUDPanel`) WAJIB memiliki `Image.raycastTarget = false` agar sentuhan mobile dan klik mouse pemain tidak terblokir saat menggeser token/hero di grid.
* **Clean Visual Hierarchy & Anti-Clutter:** Area arena pertempuran dan barikade benteng wajib bersih, lapang, dan bebas dari ornamen dekoratif yang menumpuk/membingungkan (seperti roket/menara/kubus terapung). Estetika visual harus selalu melayani keterbacaan gameplay (*Form Follows Function*).
* **Full Phase Transition Verification:** QA wajib memverifikasi siklus penuh pertempuran:
  1. *Fase Persiapan (Mode 1):* Bidak medali token dapat digeser dan difusi, sisa langkah berkurang dengan akurat.
  2. *Transisi Mode:* Saat langkah habis, token otomatis bertransformasi dengan efek dissolve & pop-up menjadi Hero Unit utuh.
  3. *Fase Tempur Aktif:* Monster muncul dari gerbang atas dan bergerak turun menuju benteng di bawah; Hero di grid otomatis mendeteksi monster dan memainkan animasi menyerang (*squash & stretch lunge*, tebasan, lontaran proyektil); monster menerima damage dan gugur dengan reward gems/gold.

### Protokol Penolakan QA & Perbaikan Mandiri (QA Rejection & Self-Improvement Loop)
* **Wajib Tolak Jika Tidak Sesuai Tujuan:** Jika QA mendapati adanya ketidaksesuaian hasil aktual dengan gameplay intent (misal bidak tidak bisa digerakkan, visual bertumpuk, atau animasi tempur tidak muncul):
  1. **QA WAJIB langsung me-REJECT** status tugas tersebut. Dilarang keras menyerahkan hasil setengah matang atau membiarkan Komandan yang harus menemukan kegagalan gameplay.
  2. QA langsung mengembalikan tiket ke **BaldHawk** disertai catatan rinci letak ketidaksesuaian.
  3. **BaldHawk secara otomatis menerbitkan Fase Perbaikan Lanjutan (Self-Improvement Phase)** ke divisi terkait (Art/Core Gameplay/Data) untuk langsung melanjutkan pengerjaan hingga 100% tervalidasi sesuai tujuan sebelum dilaporkan ke Komandan.

## 6. Proactive Continuous Improvement Protocol (SOP Radar Peningkatan Proaktif)
Sesuai arahan Komandan, alur kerja tim dipatenkan dengan standar proaktif berikut:
* **Kewajiban Pasca-Penyelesaian:** Setiap kali BaldHawk dan 4 divisi spesialis menyelesaikan suatu tugas, implementasi fitur, atau sprint, tim TIDAK PERNAH berhenti hanya pada laporan "selesai". Tim WAJIB langsung menyajikan **Radar Peningkatan Lanjutan (Proactive Next-Step Enhancements)** yang telah didiskusikan secara matang antar divisi.
* **4 Sudut Pandang Divisi:**
  1. **Asset & Art Specialist:** Estetika visual, micro-animation, sprite polish, feedback UI, dan PPU readability.
  2. **Core Gameplay & Unity Engineer:** Responsivitas game feel, ergonomi sentuhan (touch ergonomics), tempo/pacing pertempuran, juice, dan fluiditas transisi layar.
  3. **Data & Economy Balance Designer:** Kejelasan data/resource HUD, tooltip detail skill & stat, reward balancing, dan retensi jangka panjang.
  4. **QA & Code Reviewer:** Robustness arsitektur, resilience lintas rasio layar (ponsel & tablet), safe area dynamic compliance, dan zero runtime exceptions.
* **Tujuan SOP:** Memastikan game terus berkembang secara terarah, berstandar industri komersial global, dan membebaskan Komandan dari keharusan memikirkan backlog teknis dari nol pada setiap iterasi.
